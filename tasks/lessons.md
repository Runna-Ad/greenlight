[2026-08-11] LESSON (highlight-a-substring in a plain <textarea> + anchor to it): shipped "correcciones ancladas a selección". A textarea CANNOT render inline highlights and its char offsets go stale the instant the text is edited. The robust design: (1) ANCHOR OF RECORD = the quoted text snapshot (target_quote), NOT the offsets — offsets are best-effort for initial placement only; (2) live highlight via a MIRROR OVERLAY — a div behind a transparent-bg textarea, box-model-identical (same px/py/border/font/leading + white-space:pre-wrap + break-words + scrollbar-gutter:stable on BOTH so wrapping matches when a scrollbar appears), rendering the text in color:transparent with <mark> spans (mark needs explicit color:transparent — the UA sets its own color that beats the parent's); the textarea (relative, later in DOM) paints its text+caret on top, sync mirror.scrollTop on scroll; (3) BEST-EFFORT re-find: highlight if valor.slice(start,end)===quote else indexOf(quote) else nothing — so an edit that removes the phrase drops the glow while the quote stays in the panel (this IS the graceful-degrade path; unit-tested). DEPLOY-COUPLING footgun the reap caught: sending the 3 new RPC params on EVERY call makes the whole feature (incl. whole-field corrections) hard-break with PGRST202 if the frontend deploys before the migration (PostgREST resolves by arg NAME). Fix: send the quote params ONLY when there's a quote → whole-field corrections match the old OR new function signature, decoupling the common path from deploy order. And apply the additive migration to prod BEFORE git push (auto-deploy), not after. tailwind-merge gotcha: `bg-transparent` + a conditional `bg-secondary/40` → twMerge keeps the LAST bg, silently washing out the overlay; gate mutually-exclusive bg utilities. VERIFY client-rendered features on the REAL prod target (seed → load prod URL → check the <mark> in the client DOM → clean up), not only localhost.
